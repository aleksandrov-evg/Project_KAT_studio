# Серверная цель просмотра тарифов

Цель `tariffs_view` принадлежит одному компоненту `app/tariff-goal.tsx`:
браузерный `reachGoal` используется только когда серверный режим выключен.
Условие: непрерывные 3 секунды видимости половины секции (на коротком экране —
половины высоты viewport). В фоновой вкладке таймер сбрасывается. Одно событие
на открытие страницы, включая смену вкладки тарифов и последующее согласие.

## Настройки Dokploy

Добавить в Environment приложения и выполнить Deploy:

```dotenv
NEXT_PUBLIC_SITE_URL=https://YOUR-DOMAIN
METRIKA_MEASUREMENT_ENABLED=true
METRIKA_MEASUREMENT_TOKEN=YOUR-SECRET
METRIKA_MEASUREMENT_BEFORE_CONSENT=false
```

`DATABASE_URL` используется существующий. Таблица `metrika_deliveries` создаётся
автоматически; хранит UUID доставки, статус и время, без URL, ClientID и IP.
Старые записи удаляются при следующем событии спустя сутки.
Токен не должен иметь префикс NEXT_PUBLIC_, попадать в Git, клиентский код и логи.
NEXT_PUBLIC_SITE_URL должен точно совпадать с публичным origin, включая протокол.

В счётчике 112667422 включить Measurement Protocol, получить токен и создать
целевое событие с идентификатором `tariffs_view`. Проверить привязку счётчика к
кампании и затем выбрать цель в стратегии Директа после теста атрибуции.

Режим до согласия отдельно включается `METRIKA_MEASUREMENT_BEFORE_CONSENT=true`.
По умолчанию он выключен. До включения проверить основание обработки и обновить
политику/уведомление: текущий текст обещает аналитику только после согласия.
При включении событие отправляется и при явном отказе — этот режим нельзя
представлять посетителю как полный отказ от измерения рекламных конверсий.

## Данные и ограничения

После согласия используется ClientID браузерного счётчика, если его удалось
получить за 1,5 секунды. Тогда передаётся только event в существующий визит.
Без доступного ClientID создаётся случайный числовой ID на одну доставку, без
cookie/localStorage. Передаются pageview и event последовательными POST-запросами, в этом порядке.
Если pageview не подтверждён, event не отправляется.
URL очищается до origin + `/` и разрешённых параметров yclid/utm_*; фрагмент,
прочие параметры, реферер, IP, User-Agent и контакты не пересылаются. UTM-метки
должны содержать только обозначения кампаний, без персональных данных.

Получение токена доставки не загружает счётчик Яндекса. Подписанный билет
действует 10 минут, одноразовость обеспечивается PostgreSQL. Обработчик проверяет
origin, Fetch Metadata, размер тела, URL и подпись. Лимит 120 запросов в минуту
на процесс общий для GET/POST; для production дополнительно настроить лимиты
на ingress/reverse proxy. Эти проверки не подтверждают человеческий просмотр:
бот с полноценным браузером может получить билет и отправить событие.

При тайм-ауте или ошибке доставки нет автоматического повтора и браузерного
fallback, поскольку протокол не предоставляет ключ идемпотентности: иначе
возможна двойная конверсия. Статус unconfirmed/pending требует проверки, это
осознанный выбор в пользу отсутствия дублей, а не гарантия доставки.
При сбое БД отправка не выполняется.

Случайный серверный ClientID не продолжает историю браузерного посетителя.
Согласие после такого события может создать отдельный браузерный визит;
сама цель повторно не отправляется. Повторное открытие/перезагрузка страницы
считается новым открытием. Не использовать такие ID для сегментов повторных
посетителей без отдельного решения по идентификации.

## Проверка перед запуском

1. Без переменных: после согласия цель идёт браузерным reachGoal; до согласия
   нет отправки цели в Яндекс.
2. Серверный режим включён, режим до согласия выключен: до согласия POST нет;
   после согласия есть один POST `/api/analytics/tariffs` и нет браузерного
   reachGoal для этой цели.
3. На тестовом счётчике с включённым режимом до согласия: открыть реальный
   рекламный переход с yclid, посмотреть тарифы 3 секунды, проверить цель и
   источник/кампанию в отчётах. HTTP 200 от collect означает приём запроса,
   а не подтверждение атрибуции или пригодности для обучения.
4. Уход из секции до 3 секунд и фоновая вкладка не дают события. Принятие
   согласия после отправки и переключение тарифов не дают вторую цель.
5. Повтор POST с тем же билетом не отправляет данные повторно; чужой origin,
   изменённый/просроченный билет и посторонний URL отклоняются.
6. Проверить access/error-логи приложения и reverse proxy: не сохранять тела
   запросов аналитики и рекламные идентификаторы сверх необходимого срока.
