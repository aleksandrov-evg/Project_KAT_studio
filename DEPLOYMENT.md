# Production-деплой: приложение и PostgreSQL в Dokploy

Приложение остаётся сервисом типа **Application** с Build Type **Dockerfile**.
PostgreSQL создаётся и обслуживается Dokploy как отдельный сервис базы данных;
`docker-compose.yml` и собственный Postgres-контейнер в репозитории не нужны.

## Создание PostgreSQL в Dokploy

1. Откройте нужный Project → **Create Service** → **Database** → **PostgreSQL**.
2. Задайте имя сервиса, имя базы, пользователя и длинный пароль. Сохраните и
   нажмите **Deploy**.
3. Откройте вкладку **Connection** созданной базы и скопируйте значение
   **Internal Connection URL**. Это строка вида
   `postgresql://user:password@internal-host:5432/database`.

Не используйте External Connection URL для приложения: внутренний адрес не
публикует базу в интернет и работает только между сервисами Dokploy.

## Подключение приложения

1. Вернитесь в сервис Application этого репозитория.
2. Во вкладке **Environment** добавьте переменную `DATABASE_URL` и вставьте
   скопированный **Internal Connection URL**.
3. Сохраните переменную и нажмите **Deploy**.
4. Откройте `https://<ваш-домен>/api/health`: ожидается HTTP 200 и
   `{"status":"ok"}`. При первой успешной проверке приложение создаст
   таблицу `leads`.

Строка подключения доступна только на сервере: не создавайте переменную с
префиксом `NEXT_PUBLIC_` и не записывайте её в Git.

## DBeaver

Для доступа с компьютера во вкладке базы **Connection** укажите свободный
**External Port (Internet)** и сохраните. Dokploy покажет External Connection
URL. Используйте его в DBeaver как PostgreSQL-подключение. После работы с базой
внешний порт лучше убрать или ограничить firewall/VPN.

## Резервные копии

Настраивайте резервное копирование на уровне базы Dokploy во вкладке
**Volume Backups**. Перед изменением схемы или удалением сервиса проверьте, что
созданный бэкап можно восстановить.
